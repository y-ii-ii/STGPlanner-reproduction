# STOP/ACK派发与近墙恢复修复（2026-11-17新轮次）

保留成功单机04、Old dual02、上轮所有源/程序/结果；新scope为`TOPOLOGY_DISPATCH_LIMITS_20261117.json`，最多4次新双机Scene4，每次含启动收尾wall/sim≤2400秒，启动失败/中止也计数。新`team_topology_dispatch_native_20261117_ws`与`team_topology_dispatch_20261117_ws`，不替换旧空间。

## 修改及原因

- `ControlPlannerInterface`：拓扑模式的空规划结果表示WAIT/BLOCKED/观测完成，不再由PCI重复停车。协调者的STOP租约和独立最终门控继续约束运动；显式停止、任务结束、规划失败/超时仍需停车RPC。旧逻辑会在ACK派发新任务后收到上一轮空结果的STOP，取消刚派发的任务。
- `ExecutionSupervisor`：取消“任一车停机就阻塞全部新任务”的全队屏障。新接收者只等待同task、同成员或未知任务支撑相交的旧拥有者停车证明；独立任务可以派发。实际运动仍受新鲜里程计、交通预约、执行器许可和墙体制动门控限制。相同请求ID的重传不重置空闲STOP，新ID仍需要新证明。
- `StopProofCache`：ROUTE到达不能删除已经生成、尚待RPC交付的STOP证明；重传可复用只限同一个连续停车epoch。按STOP nonce绑定epoch而不是按回调到达时间绑定，防止“旧证明在新ROUTE后才到达”冒充新停车。新运动使复用失效；新请求的等待分支另外核对证明stamp不早于请求时间。旧ACK不能解锁新操作。
- `Explorer`：空闲规划使用0.15s wall退避，固定栈身份只读取一次，避免去掉停车RPC后变成高频忙轮询。
- `bodyRoute`：旧恢复加权代价1最多只允许约0.67m倒退。现在独立限制实际恢复路程≤3m、加权代价≤6；优先采样检查直线退离和原地转向，再用朝向格点后退/转向。全程车身+0.05m必须已知自由，未知/占据不放行；终点要求0.18m余量，为正常0.15m及执行误差留出缓冲。目标暂缓/空引导也能在有效任务租约下恢复，恢复不冒充探索完成。
- `PathExecution`：恢复终点同时检查8mm位置和0.02rad朝向；跟踪器使用更小终点容差。零位移转向不能因位置已满足就立即宣布成功。普通路径保留原探索/任务约束。
- 普通平移上限2m/s、角速度上限60°/s对齐成功对照；角向制动模型采用60°/s²，线向按2m/s²保守检查。恢复仍限0.2m/s、0.3rad/s。控制律仍不同，不能称所有控制细节相同的纯分配消融。
- 试验增加实际任务命令日志、执行/控制库与Explorer二进制校验，以及最终独立请求的完整停车证明检查。原世界/URDF/底盘配置/原版评分器和0.4m、12m、7790m²分母/7400.5m²阈值不变。
