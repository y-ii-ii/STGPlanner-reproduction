# STGPlanner拓扑协同首阶段离线实施报告

日期：2026-11-16。状态：共同world、完美通信下的首版核心与原生接口已实现，离线检查及隔离编译通过；没有启动仿真、ROS节点或原生地图重放。它是独立候选，未替换成功单机04或Old dual02。

## 1 本轮完成内容

|部分|实现了什么|为什么这样修改|
|---|---|---|
|拓扑导出|本车原STG端点／连接经本车已观测自由栅格A*验证，生成带真实折线路径的来源节点／边|抽象边或端点直线不能保证物理可达；保留原STG结构入口并记录实际可执行候选几何|
|增量交换|机器人＋会话＋本地键，逐记录版本，删除tombstone、原子收包、幂等和缺包全量修复|避免不同车辆Boost标签冲突、旧包复活删边和收一半图造成错误|
|拓扑融合|共同world中，在不同来源已验证路径采样点精确重合时建立导航连接；保留原始来源记录|平行走廊仅仅靠近不能直接连边；不向原Boost图强塞远端ID|
|连通任务|4m格仅作索引，按free／unknown连通分量及可达入口生成任务，包含跨格入口|同一格隔墙两侧不是一个任务；格边界不能使真实前沿消失|
|任务生命周期|入口区域重叠跟踪身份；拆分／合并／重新出现有谱系；按本车已观测证据完成，否则deferred|入口代表点小幅变化不应反复新建任务；空候选、超时、暂时无路都不等于完成|
|分配|融合图最短路径＋机器人到自身格心的挂接距离；任务多个入口取最小代价，只分配一个owner|避免隔墙直线距离误分配；本轮只实现选择的图距离方法，不凑齐其他算法|
|任务承诺与交接|已派发即保留责任；未执行任务可offer→接收ACK；旧版本ACK拒绝，失败交接回滚|防止ACK延迟期间被另一辆车抢占；失败不标记任务已探索|
|规划接口|新模式通过原Action结果接口输出最多4m的当前本车已知自由车体路径前缀|融合图可用于路线计算与原生路径入口，而非仅可视化；当前未知或障碍处截断|
|通信统计|实际JSON／ROS String序列化发布字节及机器人距离；周期全量修复同样计入|先量数据，不施加半径／带宽限制，不把应用字节当无线流量|

新模式关闭远端点云订阅及旧4m归属话题，团队协调器只接收拓扑／任务摘要／机器人状态。本车私有完整栅格仅传给本车adapter，不广播给团队；评分器和历史计分代码未修改。

分配采用一个完美通信下的中央权威提交归属，不宣称已完成分布式一致性。基础图距离分区、任务承诺和闲车交接是独立机制；最近分配仍不保证负载最均衡或总路程最短。

## 3 参考方法与本项目适配

- [GVP-MREP，IROS 2024](https://arxiv.org/abs/2408.05808)：借鉴动态拓扑增量交换、图距离分区和本区结束后协助的方向。本实现采用地面车连通任务和任务承诺，不移植UAV轨迹生成，也不照搬其EROI终止阈值。
- [C²-Explorer](https://arxiv.org/abs/2603.07699)：借鉴free／unknown连通关系与入口组织任务。本实现的任务身份、摘要去重及阶段性协议是适配；没有将其map chunk共享称为纯拓扑方案。
- [MGGPlanner](https://github.com/MISTLab/MGGPlanner)：借鉴跨机器人全局图共享方向。当前仅共同坐标关联，不是SLAM回环检测。
- OmniPlanner／GBPlanner的DTW聚类留在后续独立模块；本轮没有声称已实现。距离贪心、MinPos和MDVRP继续仅作候选参考。

新增核心为独立实现，没有复制上述仓库算法源码。原planner保持原有许可声明，不将新增Python包的许可扩展到上游代码。

- 两车获得不同任务，分别指向左右分支。
- 融合图查到10m跨来源路线，包含robot2来源边；这是路线计算验证，不是车辆已在仿真走过。
- 初始两次拓扑／任务发布共5477字节；地图／图不变后的两次状态心跳共377字节。两者载荷不同，仅说明增量机制生效，不能据此声称比旧点云通信节省某个百分比。
- robot1补齐原未知区域观测后，其任务报告completed；robot2任务不被错误完成。
- 未读真实未知地图，未传完整点云／占据栅格；没有新的Scene4覆盖率或T95。

诊断记录也保留：首次默认PIE ASan运行异常，非PIE版本完成相同检查；根因未完全证明。第一次编译本体成功，但运行中编辑包装脚本导致收尾错误；第一次冻结脚本又因CRLF被拒绝。最终改用LF冻结脚本后编译退出0。这些都是离线构建／检查，不是新增正式仿真次数。

## 6 仍存在的问题和后续边界

1. 尚未在线验证车辆实际使用同伴边、全空间持续探索、95%覆盖和T95；原生接口能编译不等于这些已经通过。
2. 当前已知world精确关联不能完成估计位姿下的拓扑匹配或回环；保守精确重合也可能漏连。
3. 不同观测摘要可能保留重复任务。最近分区还可能工作量不均、共用走廊和跟随，不能提前保证更快或总路程更短。
4. 导航搜索目前展开边采样点；任务、路径生成及图索引尚需规模化剖析，稀疏拓扑通信不等于本机计算已最优。
5. ACCEPTED只表示原生规划器接受当前局部前缀，不是车辆到达或物理停止ACK；活动任务转交、执行超时及动态双车避让必须另验。
6. 任务仅在先前未知分量真正被本车观测后完成；当前无自动全局结束证明，不能因空候选结束任务。
7. 机器人／协调器进程换会话当前拒绝并要求显式重建，断联、跨会话恢复及真正回环仍在后续阶段。
8. 旧成功planner本身已有的潜在内存／边界问题未在此次拓扑功能中一并修复；旧源码和失败候选都保留。

后续优先核验任务约束与原STG局部选点的接入方式，做规模化离线剖析及执行器停止接口检查。新的在线运行须另有明确有限次数与时限，再按同Scene4、同速度、同公共并集评分进行95%／T95对照；本轮不自动启动。
