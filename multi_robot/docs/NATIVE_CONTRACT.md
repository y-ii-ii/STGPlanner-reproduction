# 原生接口和离线验收边界

## 数据流

每辆车的雷达仍只更新本车 UFOMap／局部地图和原STG结构。新模式在原生 planner 中导出本车拓扑与本车栅格快照到本车私有 topic；本车 topology_agent 依据观测自由空间验证路径、生成连通任务，只把 GraphDelta 发往团队。topology_coordinator 只收到图、任务摘要与机器人状态，按图距离分区、承诺任务和生成带来源边的路线。

私有接口（i为车号）：

|话题|生产者→消费者|内容与范围|
|---|---|---|
|/robot_i/topo_planner_node/topology_snapshot|本车native→本车agent|仅本车栅格、原STG节点连接和位姿；不广播给团队|
|/team/topology_delta|各车agent→协调器|带来源／会话／版本的拓扑、任务摘要、状态及删除记录；无完整点云／栅格|
|/robot_i/topo_planner_node/topology_command|协调器→对应native|带任务版本、派发序号和协调器会话的路线／等待|
|/robot_i/topo_planner_node/topology_feedback|对应native→协调器|当前局部路径前缀验收反馈；数值兼容property_tree字符串编码|

单一协调器是本阶段完美通信下的归属权威，不称为分布式共识。图Voronoi距离由同一融合图的最短路径计算；承诺保持／合法交接在基础距离分区之外单独处理。未执行任务可以offer→ACK交接，已经执行或已经派发的任务不得被静默抢占。

## 原生模式隔离

- 默认 team/topology_enabled=false，保持旧入口。原成功配置、源目录和原生库完全不改。
- 新独立 planner 加载 team_topology/config/world_perfect.yaml；每车单独设置 team/robot_id。必须 world、至少两车，禁止 shared_sensor_mapping。
- 新模式不订阅远端点云，也不订阅旧 /team/native_ownership。
- 继续使用原生 updateTopo 维护本车STG；探索目标与全局路线由新任务／融合图接口决定，**新模式不完整沿用原五状态目标选择链**。最终路径仍交给现有控制接口；旧模式可独立保留。
- 形态学处理后的白像素不能冒充观测自由空间。原生快照联合原始观测状态；未知像素仍未知，避免凭图像扩张虚构导航边或任务完成。
- 全局远端路线进入执行前，使用本车当前 executionGrid 按车体范围、沿路径与转角采样检查，最多发出4m的已知自由路径前缀；未知／障碍处截断，不能调用旧终点修复的unknown例外。

## 尚未在线验收的边界

本轮只有合成输入、离线编译与函数检查，没有启动 roscore、ROS节点、Gazebo或原生地图重放。

1. 含同伴边的路线已在离线融合图中计算，并接到原生 Action 结果生成入口；尚未证明车辆已在仿真实际执行这些边。
2. ACCEPTED 是原生规划器接受了局部路径前缀，不等于车辆实际到达或物理停车ACK。已经执行的任务转交需要明确释放；物理停车、已有执行器的命令超时和动态双车避让仍需后续有限额度的在线验收，不能据本轮代码宣称安全闭环通过。
3. 任务完成来自本车地图中上一未知分量已全部观测的证据，不按空候选、超时或暂时不可达完成。没有候选也不会自动宣布全局探索完成；当前不自行给出任务终止证明。
4. 固定共同world、栅格原点和分辨率。只在共同路径采样位置精确重合时关联，隔墙近平行路线不合并；保守关联仍可能漏连。机器人或协调器会话替换采用拒绝并要求显式重建，尚未实现断联／进程重启恢复。
5. 不同本车观测导致未知分量摘要不同，仍可能形成部分重复任务；基础分区也不保证负载均衡或总路程最小。没有新95%／T95／速度提升结论。
6. 当前通信统计是应用层ROS String序列化字节，包括4字节字符串长度，按发布次数计；不包括链路头、额外订阅者复制、重传和物理无线流量。完美通信阶段没有半径／带宽门控。
7. 当前新增边以本车已观测自由空间A*验证原STG端点间路径，实际几何可能与原骨架边不同；记录真实折线并据此计费，不将端点直线或原抽象边权当成安全路径。
8. 未引入真实回环、位姿优化、DTW稀疏化、MinPos或MDVRP，也没有将新候选替换为已验证的成功基线。

## 编译和离线检查

编译脚本只复制本目录两个源码包到全新隔离原生工作空间，不修改旧成功workspace：

    bash multi_robot/build_offline.sh

测试脚本必须提供新的证据目录，不调用旧run.py：

    bash multi_robot/test_offline.sh /path/to/new/offline/evidence

其Python单元测试不需要ROS，C++检查使用ASan/UBSan非PIE构建。默认PIE的首次ASan检查曾异常退出并递归打印信号；保留失败记录，非PIE构建完成相同用例并通过。全量native编译验证接口可编译，不代替运行验收。

collaboration.launch 仅提供适配器连接，不启动仿真或车辆；本轮没有执行它。后续启动前须按最新STATUS／仿真锁及新的有限实验授权处理，不能从这里推断已经获得启动权限。
