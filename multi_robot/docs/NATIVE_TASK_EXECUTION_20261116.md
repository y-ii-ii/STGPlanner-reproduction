这里的“修改前”指首阶段候选5af86c0；成功单／双机和最初STGPlanner均未覆盖。

|2 选择遗漏分支|原updateCurrentExploreBranch筛选当前任务候选；保持成功源码现有距离规则，不能称逐项复现论文窄分支优先|
|3 历史回溯|仅借用任务内的历史分支；未归属标签及其路径／距离保留并恢复；无候选安全返回|
|4 UFO边界补充／恢复|本地及全局UFO前沿和恢复入口仍须命中任务unknown／portal，不使用接近带放宽边界任务|
|5 路径生成与执行|进入原planning／A*；目标须有本任务证据，再通过本车地图的车体前缀检查|

入口接近带由portal起，沿本车已知Free且形态学可通行的4邻接格扩展，深度最多min(8格, ceil(1米/分辨率))；它不把未知变成可执行空间，不跨墙扩张。若本任务暂时没有有效原生局部候选，则使用该任务的融合图路径接近；最终仍只输出本车当前可验证的最多4米前缀。共享通道可经过，探索目标受任务约束。

图融合和全局任务选择沿用首阶段：不同来源的已验证自由路径采样点在共同world精确重合才连接；图最短距离分配、派发承诺与闲车协助。中央不订阅点云、完整占据图或Gazebo真值；本车完整快照只送本车适配器。已下发任务支持B按其观测完成，但未知区域若无法被单一执行者完整观测，仍可能长期deferred；尚未支持按多车部分观测合并完成证明。

## 3 停车确认与超时

执行链为：任务命令 → 原生任务内规划 → 带租约的Action结果 → 控制接口 → 执行器发布新路径 → 跟随器raw_cmd_vel → 本车最终速度门控 → cmd_vel。

停车证明必须同时满足：本次停止请求之后时间递增且新鲜的里程计至少3帧；twist及位姿差分均在0.05米/秒、0.09弧度/秒内持续至少0.5秒；门控已向ROS成功提交零速输出至少0.5秒，最近输出仍新鲜。这是软件观测证明，尚未通过Gazebo物理停车验收，也不证明底层电机收到每一条消息。

|保护|默认值与处理|
|---|---|
|协调器命令|1.5秒失效归零|
|执行器许可|0.3秒失效归零，进程退出不会继续沿用旧许可|
|里程计／跟随速度|约0.3秒失效保护；旧／冻结里程计不能生成停车ACK|
|原生规划请求|5秒，失败／空路径取消执行并请求停车|
|单个执行Goal|30秒；同代次整体上限60秒|
|停滞|8秒无累计0.1米位移触发，不能靠频繁换Goal续期|
|停止屏障／服务／客户端|6／7／7.5秒；超时故障，迟到ACK不能自动恢复|
|失败反馈|规划阻塞暂缓该车任务2秒；停滞／整体超时暂缓8秒，释放仍等停车证明|

所有新增保护使用单调时间，不因ROS仿真时钟暂停而停止计时。新代次先发布新路径，再释放跟随器和授予许可；首次许可清理旧速度缓存。门控本身崩溃后的停车仍依赖底层控制器命令看门狗，未在线验证。
