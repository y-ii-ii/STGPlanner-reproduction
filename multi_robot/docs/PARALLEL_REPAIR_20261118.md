# 提高双机同时推进时间

上一轮03的起始通道覆盖几乎不变，交通记录进入39个让行轮次。上一轮04记录119个任务变更STOP和59个规划受阻STOP。其原生规划反馈中有132条 `DEFERRED_TASK/BODY_NO_PATH`、29条到接近点的 `BODY_NO_PROGRESS`。反馈消息可重复，STOP按nonce去重。

- `traffic.py` 允许同一通道内、朝向接近且均请求直行的两台车同时推进。沿通道净距需覆盖后车实测或请求速度的制动距离，考虑0.4秒感知与许可延迟、2 m/s²制动模型和原有0.24 m车间余量。较近时只缩减后车，沿用原扫掠和实测速度扰动检查。相向、转弯、间距不足依旧进入原有制动和让行机制。已进入BRAKE或RETREAT时，由原状态机先完成当前阶段。
- `allocator.py` 在已派发任务短时消失时，以当前图重新搜索原入口，有合法路径且仍需观测才保留原合同，最长2秒。冷却、完成证明、过期状态或入口不可达按既有STOP/ACK处理。新竞标依次尝试其他可达入口，避免把最近入口的空间退避当成整个连通任务不可达。
- `task_approach_route.h` 在原生路径和分配路径无法执行时，检查同一任务的本车已知自由接近带，从最多12个候选中选择最长2.6 m的直行或先转后直行前缀。沿途检查车身体积，保留0.15 m基本余量并优先0.22 m。候选仍受本地延期和规划时效约束。原先原生路径失败后的全局路线回退补上了延期检查。

离线用保存轨迹按每8个交通采样选取一个时间点，并关联过去100 ms内两车的实际位姿、测得速度和请求。上一轮03的197个双车运行重叠路径采样有16个符合新同向规则，其中首个旧记录为双HOLD。试算通过样本的最小扫掠净距为0.276 m。采样分析未重启仿真，实际推进和接触由新试验记录。

同一Scene4、平移2 m/s和转向π/3 rad/s上限，评分器与0.4 m独立评分格并集沿用成功基线。以两车平移速度绝对值均大于0.05 m/s的同期里程计采样时间统计并行推进率，另外报告相同120秒累计路程和覆盖，与历史wall T95分开列示。
